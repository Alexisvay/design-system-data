Reading the naming…
The rules in short — full reference in nomenclature-composants.md, shipped with this plugin
  • Props in kebab-case, values lowercase: hierarchy / primary, not [🎨] Hierarchy / Primary.
  • One axis = one decision. A prop that mixes two things (style=primary-large) splits into hierarchy and size.
  • States live in one place, and disabled lives in state (enabled, hover, focus, press, disabled) — never as an is-disabled boolean, which would let hover + disabled exist.
  • Booleans are prefixed: show-* for visibility, is-* for states.
  • The name never carries the type: no icon-swap, no label-text — the data is already typed.
  • Content props take the name of the layer they fill: the prop label fills the layer …label, the prop icon-left fills the instance icon-left.
  • Shared vocabulary across components: state, size, hierarchy, tone, type, status, validation, selection, shape, placement, orientation.
  • Layers: the same element keeps the same name in every variant, named by role (icon-left, checkbox-label, card-header) — never Vector or Rectangle 2.
  • A nested instance takes the role it plays here, not the name Figma copied from its source (item, not _Bottom-bar-item) — the underscore only ever means “internal component”, and a layer is neither public nor internal.
Documentation · the judgment layer

The extraction reads the measurable (props, styles, states). The doc brings what no tool can guess: description, usage rules, accessibility, examples. One markdown per component, merged verbatim into the JSON.

Convention: ## Description, ## Role, ## Platforms, ## States, ## Interaction, ## A11y, ## Behavior, ## Writing, ## Forbidden, ## Examples — full reference in doc-composant.md, shipped with the kit. Skippable, but without it 8 of the 13 checklist points stay unchecked.
